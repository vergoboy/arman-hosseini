# arman-portfolio

Bilingual (English / Persian) personal site for **Arman Hosseini** — Software Engineer
(Rust, Linux systems, networking, hardware reverse engineering).

Built with **Astro + TypeScript + Tailwind CSS v4** in a "modern CLI / terminal" theme:
zinc surfaces, a rust-orange accent, Inter for English and Vazirmatn for Persian.

## Stack

- **Astro 7** — static output, no client JS bundle.
- **Tailwind CSS v4** — CSS-first theme; tokens live in `src/styles/global.css` (no `tailwind.config.js`).
- **@astrojs/mdx** + **Content Collections** — project and journal notes are authored in Obsidian and synced into `src/content` (`.mdx` through MDX, `.md` through Astro's Markdown pipeline).
- **@lucide/astro** — UI icons; brand glyphs are hand-rolled in `src/components/BrandIcon.astro`.
- **@astrojs/sitemap** — emits `sitemap-index.xml` + `sitemap-0.xml` with `hreflang` alternates.
- Self-hosted fonts via `@fontsource-variable/*` (Inter, JetBrains Mono, Vazirmatn).

## Commands

```sh
npm install
npm run dev            # local dev server
npm run build          # astro check + static build to dist/
npm run preview        # preview the built site

npm run sync:content   # vault → src/content (see “Content pipeline”)
npm run check:content  # fail if src/content is out of date (CI)
npm run deploy         # build + publish dist/ to the server over SSH
npm run deploy:dry     # build + show what the deploy would change
```

## Routing & languages

| Route            | Language | Direction |
| ---------------- | -------- | --------- |
| `/`              | redirects to `/en/` | —    |
| `/en/`           | English  | `ltr`     |
| `/en/about/`     | English  | `ltr`     |
| `/en/contact/`   | English  | `ltr`     |
| `/en/projects/`  | English  | `ltr`     |
| `/fa/` …         | Persian  | `rtl`     |

English is the default language (`/en/`), Persian is served from `/fa/`, and `/` redirects
to `/en/` (configured in `astro.config.mjs`). Every page emits `hreflang` alternates plus an
`x-default` pointing at the English version.

```sh
npm run dev   # then open /en/ or /fa/
```

## Content pipeline

Notes are written in Obsidian and published to the site:

```
Obsidian vault                    GitHub                 this project                    server
project/{en,fa}/…mdx  ─push─▶  (FIT plugin)  ─sync─▶  src/content/…  ─build─▶  dist/  ─rsync─▶  /opt/arman-hosseini
journal/{en,fa}/…md    sync:content                Astro collections        deploy.sh
```

`npm run sync:content` copies the vault's publishable folders into the Astro content
directories, which the content collections read:

| Vault                     | Collection                 |
| ------------------------- | -------------------------- |
| `project/{en,fa}`         | `src/content/projects/{en,fa}` |
| `journal/{en,fa}`         | `src/content/journal/{en,fa}`  |

The vault path defaults to `/home/arman/Documents/obsidian/arman/arman-hosseini`; override it
with `--vault <path>` or the `OBSIDIAN_VAULT` environment variable.

**Synced files are generated and git-ignored** — the vault is the source of truth, so a
fresh clone has empty collections. The site still builds: project pages fall back to the copy
baked into `src/i18n/translations.ts` (and the journal simply shows an empty state). Once the
vault has entries, they take precedence and the built-in copy is unused.

### Frontmatter

The Zod schemas live in `src/content.config.ts` and are strict — a file that does not match
fails the build rather than rendering something surprising.

| Key | Required | Notes |
| --- | -------- | ----- |
| `title` | ✅ | Card/list title and `<h1>` |
| `date` | ✅ | `YYYY-MM-DD`; sorts listings (newest first) |
| `tags` | ✅ | Array of strings |
| `lang` | ✅ | `en` or `fa`; must match the folder — checked at build time |
| `slug` | — | URL segment; `sync:content` writes it from the file name |
| `summary` | — | Card excerpt and page meta description |
| `draft` | — | `true` hides it from listings and routes |
| `tagline`, `highlights`, `featured`, `span`, `links` | — | Projects only |

`sync:content` fills `title`/`date`/`lang`/`tags`/`slug` when they are missing — `date` from
the file's mtime, `title` from the file name — so a note with no frontmatter at all still
publishes. It edits frontmatter **line by line**: your own key order, comments and body are
left untouched. A note deleted or renamed in the vault is pruned from `src/content`.

`slug` accepts Unicode letters, so a Persian note named `برنامه هفتگی` publishes at
`/fa/journal/برنامه-هفتگی/`. Keep file names to plain ASCII or Persian for readable URLs;
anything else falls back to a short stable hash.

`.md` files stay `.md` and are **not** parsed as MDX, so a note containing `{` or a literal
`<Tag>` publishes safely. Only `.mdx` files get MDX parsing — use that extension when you
want expressions (`{2 + 2}`), JSX components or `import`s.

> Not translated yet: Obsidian-specific syntax such as `[[wikilinks]]`, `![[embeds]]` and
> `==highlights==`. Use standard Markdown links and images in notes you publish.

### The rest of the copy

**All site chrome and body copy — including the built-in project fallback — lives in
`src/i18n/translations.ts`.** English is the source of truth for the shape: `fa` is typed as
`typeof en`, so adding a key in one language without the other is a type error.

- `useTranslations(lang)` → the whole dictionary (arrays, timeline, project copy).
- `t('nav.about', lang)` → a single dotted string key.
- `localizedPath(lang, 'about')` → `/fa/about/`; `switchLangPath(path, 'fa')` → same page, other language.

Language-neutral facts live in `src/data/site.ts`:

- `site` — name, `alternateName` (Persian name), domain, emails.
- `projectMeta` — fallback project `slug`, page order, bento `span`, `featured`, `links`. Used
  only while `src/content/projects` is empty.

## Editing content

- **New project or journal note** → write it in the vault under `project/{en,fa}` or
  `journal/{en,fa}`, then `npm run sync:content`.
- **About / contact / nav / footer / site copy** → `src/i18n/translations.ts`.
- **Identity, emails, fallback project structure** → `src/data/site.ts`.
- **How vault content is read** → `src/data/projects.ts` and `src/data/journal.ts`.

## Theming

Dark ("Modern CLI") is the default; light is a clean white/zinc variant with the same accent.

- Tokens are plain CSS variables: `:root` holds the light palette, `.dark` overrides it, and
  `@theme inline` maps them to utilities (`bg-page`, `bg-surface`, `border-line`, `text-primary`,
  `text-muted`, `text-accent`).
- `<html>` ships with `class="dark"`, so the default theme needs no JavaScript. A small inline
  script in `Layout.astro` switches to light when `localStorage.theme === 'light'` and handles
  clicks through one delegated listener — hence zero JS files in `dist/`.
- Persian typography is switched by `html[lang='fa']`, which swaps `--font-body` / `--font-code`
  to Vazirmatn.

## RTL notes

- `Layout.astro` sets `dir="rtl"` for Persian; layout uses logical properties
  (`ps-*`, `ms-*`, `border-s`, `start-*`) so spacing mirrors automatically.
- Directional icons flip with `rtl:-scale-x-100`, and terminal commands / handles are wrapped in
  `<span dir="ltr">` so they are not reordered by bidi.

## Deployment

`site: 'https://arman-hosseini.ir'` in `astro.config.mjs` drives canonical URLs, OG tags and the
sitemap.

`npm run deploy` builds and publishes `dist/` to `/opt/arman-hosseini` with **rsync over SSH**
(incremental, resumable, and it prunes files that no longer exist locally — a plain SFTP
upload cannot).

### Setup

1. Fill in non-secret settings in **`deploy.config.json`**:

   | Key | Meaning |
   | --- | ------- |
   | `host`, `port`, `user` | SSH target (leave `host` empty to use `--local` staging) |
   | `remotePath` | Server directory for `dist/` contents — `/opt/arman-hosseini` |
   | `identityFile` | Private key, e.g. `~/.ssh/id_ed25519` |
   | `localDir` / `buildCommand` | Build output and how to produce it |
   | `delete` | Remove server files that are gone from `dist/` |
   | `exclude` | rsync `--exclude` patterns |

2. Put secrets in **`.env`** (git-ignored; copy `.env.example`). Key auth is preferred — only
   set `DEPLOY_SSH_PASSWORD` if the server refuses keys, which additionally needs `sshpass`.
   `deploy.config.json` is committed, so the script **refuses to run** if it finds a
   credential there.

3. Deploy: `npm run deploy` — or `npm run deploy:dry` to see the file list first.

Commands:

```sh
npm run deploy                                  # build + publish
npm run deploy:dry                              # build + show what would change
scripts/deploy.sh --skip-build                  # re-upload the existing dist/
scripts/deploy.sh --local --skip-build           # sync to remotePath as a local dir (staging)
```

A passphrase-protected key must be loaded into `ssh-agent` — the script runs SSH in
`BatchMode` so it fails fast instead of hanging on a prompt. First contact with a new host
uses `StrictHostKeyChecking=accept-new`.

### Triggering it after a vault sync

The FIT plugin in the vault can run this pipeline automatically: enable **Post-sync hook** in
FIT settings, set the command to `bash /path/to/this/repo/scripts/deploy.sh`, and the working
directory to this repo. It runs only after a sync that actually pushed a commit to GitHub,
only on desktop, and never on mobile.

After the first deploy, register the domain in **Google Search Console** and submit
`https://arman-hosseini.ir/sitemap-index.xml`.
