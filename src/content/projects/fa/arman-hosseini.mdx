کاری که یک سایت ایستا را جذاب می‌کند خودِ HTML نیست، بلکه مسیری است که یک ایده از یادداشت تا نشانی عمومی طی می‌کند. این صفحه هر بخش را به فایل مربوطه در مخزن نسبت می‌دهد و توضیح می‌دهد لایه سئو و امکانات پاسخ‌گویی ماشین بدون پایگاه داده چگونه سرهم شده‌اند. اگر می‌خواهید همین مسیر را گام‌به‌گام ببینید، [سایت چگونه ساخته شده است](/fa/journal/how-this-site-works) را بخوانید.

## چرا یک سایت دوزبانه بدون CMS منتشر کنیم؟

یک CMS وقتی به کار می‌آید که ویرایشگران متعدد و امکانات پویا در میان باشند. برای نویسنده‌ای که بیشتر نثر می‌نویسد، CMS یک پایگاه داده، مجموعه‌ای افزونه و یک زمان اجرای قابل نگه‌داری اضافه می‌کند. پیش‌ساختن صفحه‌ها همه این‌ها را حذف می‌کند: مرورگر HTML آماده می‌گیرد، محتوا زیر کنترل نسخه می‌ماند و موتورهای جست‌وجو و موتورهای پاسخ می‌توانند هر صفحه را بدون اجرای جاوااسکریپت بخوانند. بهایش این است که انتشار یعنی ساخت دوباره، نه یک کلیک در ویرایشگر مرورگری.

## سایت چگونه ساخته، ویرایش و منتشر می‌شود؟

Astro در زمان ساخت همه مسیرها را به HTML کامپایل می‌کند. یک سرویس جداگانه Node بدون وابستگی زیر `admin/` محتوا را مدیریت و نسخه‌های تازه می‌سازد، و nginx هر نسخه‌ای را که پیوند نمادین `current` به آن اشاره می‌کند ارائه می‌دهد. این پیوند تنها پس از موفقیت یک ساخت جایگزین می‌شود، پس یک ساخت خراب هرگز به بازدیدکننده نمی‌رسد.

پروژه در چهار لایه سازمان یافته است:

1. **نمایش** — مسیرهای Astro در `src/pages/` صفحات خانه، درباره، پروژه‌ها، یادداشت‌ها، برچسب‌ها و تماس را می‌سازند، به‌همراه `404`، `sitemap.xml`، `robots.txt`، `llms.txt`، فید RSS هر زبان و web manifest.
2. **محتوا** — فایل‌های Markdown و MDX زیر `src/content/{projects,journal}/{en,fa}` که با طرح‌واره `src/content.config.ts` اعتبارسنجی می‌شوند.
3. **SEO/AEO** — `src/lib/seo.ts` هر ورودی را به فراداده صفحه، کارت Open Graph/Twitter و یک گراف JSON-LD تبدیل می‌کند.
4. **مدیریت و انتشار** — سرویس Node در `admin/` محتوا را ویرایش و نسخه‌ها را می‌سازد، و `deploy/` آن‌ها را از طریق nginx ارائه می‌دهد.

## سایت و پنل مدیریت چه کارهایی می‌توانند انجام دهند؟

| قابلیت | چه می‌کند | کجا قرار دارد |
| --- | --- | --- |
| صفحات دوزبانه | انگلیسی و فارسی با چیدمان RTL و hreflang، وقتی یک جفت `translationKey` مشترک داشته باشد | `src/content/`، `src/lib/content.ts` |
| فراداده SEO/AEO | عنوان، توضیح، کلیدواژه، canonical، Open Graph، کارت‌های Twitter و JSON-LD برای هر صفحه | `src/lib/seo.ts` |
| خروجی‌های خوانا برای ماشین | `sitemap.xml` (با hreflang و `lastmod`)، `robots.txt`، `llms.txt`، RSS و web manifest | `src/pages/` |
| کامپوننت‌های داخلی MDX | `Callout`، `Card`، `Tabs`/`Tab`، `YouTube`، `AudioPlayer`، `VideoPlayer` — بدون نیاز به import | `src/lib/mdx-components.ts` |
| پنل مدیریت | ویرایش SEO، رسانه، ترجمه‌ها، وضعیت پیش‌نویس/غیرفعال، آمار و بازگردانی | `admin/` |
| انتشار از Obsidian | نوشتن MDX در Obsidian، کامپایل و ارسال، سپس تأیید در صندوق ورودی پنل | نقاط پایانی `/api/studio/` پنل |
| انتشار اتمیک | هر ساخت در `releases/<timestamp>` می‌نشیند؛ پیوند `current` فقط در صورت موفقیت جابه‌جا می‌شود | `admin/lib/build.mjs` |

## چطور آن را محلی اجرا کنم؟

پیش‌نیازها: Node.js 20 یا بالاتر (خط لوله CI روی Node 22 می‌سازد) و npm. زمان اجرای دیگری لازم نیست؛ سرویس مدیریت فقط از کتابخانه استاندارد Node استفاده می‌کند.

```bash
git clone https://github.com/vergoboy/arman-hosseini.git
cd arman-hosseini
npm ci
npm run dev        # سرور توسعه محلی
npm run build      # astro check && astro build → dist/
npm test           # تست‌های API پنل (node --test admin/test/*.test.mjs)
```

دستورهای معتبر `package.json` این‌ها هستند:

| Script | دستور | کاربرد |
| --- | --- | --- |
| `npm run dev` | `astro dev` | سرور توسعه محلی |
| `npm run build` | `astro check && astro build` | بررسی نوع و ساخت در `dist/` |
| `npm run preview` | `astro preview` | پیش‌نمایش خروجی ساخته‌شده |
| `npm test` | `node --test admin/test/*.test.mjs` | تست‌های API پنل |
| `npm run admin` | `node admin/server.mjs` | اجرای سرویس مدیریت (پیش‌فرض `127.0.0.1:4322`) |
| `npm run deploy` | `bash scripts/deploy.sh` | ساخت و همگام‌سازی `dist/` با سرور به‌صورت نسخه تازه |

## کدام متغیرهای محیطی قابل تغییرند؟

سرویس مدیریت و فرایند ساخت مجموعه کوچکی از متغیرهای محیطی را می‌خوانند. فقط نام‌ها — هرگز رمز یا کلید را در مخزن نگه ندارید.

| متغیر | کاربرد | پیش‌فرض |
| --- | --- | --- |
| `SITE_DIR` | ریشه سورس سایت | ریشه پروژه |
| `DATA_DIR` | پوشه داده پنل (نشست‌ها، ساخت‌ها، صندوق ورودی) | `./.admin-data` |
| `RELEASES_DIR` | محل نگهداری نسخه‌های ساخته‌شده | `./releases` |
| `CURRENT_LINK` | پیوند نمادینی که nginx ارائه می‌دهد | `./current` |
| `ADMIN_HOST` | نشانی اتصال پنل | `127.0.0.1` |
| `ADMIN_PORT` | درگاه پنل | `4322` |
| `BUILD_CMD` | دستوری که پنل برای ساخت اجرا می‌کند | `npm run build:site` |
| `KEEP_RELEASES` | تعداد نسخه‌های نگه‌داشته‌شده | `5` |
| `SITE_URL` | نشانی canonical سایت | `https://arman-hosseini.ir` |

تنظیمات انتشار که رمز نیستند در `deploy.config.json` قرار دارند (host، port، user، `remotePath`، `identityFile`، `localDir`، `buildCommand`، `exclude`). هر نوع اعتبارنامه باید در `.env` (نادیده‌گرفته‌شده در git) بماند؛ `scripts/deploy.sh` اگر `deploy.config.json` فیلدی مانند password، passphrase، privateKey، token یا secret داشته باشد، از اجرا سر باز می‌زند.

## سایت ایستا یا WordPress: کدام مناسب است؟

هر دو می‌توانند متن را در دسته‌بندی‌های متعدد منتشر کنند. تفاوت در سربار عملیاتی در برابر راحتی ویرایش است.

| جنبه | arman-hosseini.ir | WordPress |
| --- | --- | --- |
| زمان اجرا | فایل‌های ایستا که nginx ارائه می‌دهد | PHP + پایگاه داده |
| وابستگی‌ها | Node.js فقط در زمان ساخت؛ پنل بدون بسته npm | افزونه‌ها و پایگاه داده‌ای که باید نگه‌داری شوند |
| ویرایش | فایل‌های Markdown/MDX، پنل، یا Obsidian | رابط مدیریت مرورگری |
| کارایی | HTML پیش‌ساخته؛ بدون رندر برای هر درخواست | رندر برای هر درخواست (نیازمند کش) |
| تعامل | هیچ‌کدام در محتوا (سایت ایستا) | افزونه‌ها و پوسته‌ها |
| مناسب برای | یک نویسنده، متن‌محور، سریع و کم‌نگه‌داری | بسیاری ویرایشگر، بوم افزونه، امکانات پویا |

سایت ایستا اگر به حساب کاربری، دیدگاه یا محتوای متغیر با هر درخواست بدون ساخت دوباره نیاز دارید، انتخاب نادرستی است. arman-hosseini.ir عمداً هیچ‌کدام از این‌ها را ندارد.
