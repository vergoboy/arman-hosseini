arman-hosseini.ir is the personal site of Arman Hosseini (آرمان حسینی): a static, bilingual portfolio and journal generated by Astro, with an SEO/AEO layer, a zero-dependency Node admin service, and an Obsidian publishing pipeline that turns Markdown and MDX notes into atomic releases.

## What problem does arman-hosseini.ir solve?

It publishes technical writing and project notes in two languages without a database, a CMS or a client-side framework. Dynamic platforms add servers, dependencies and runtime weight for content that is mostly text; this project ships pre-rendered HTML, keeps content as files under version control, and adds one small service for editing, validating and publishing.

<Callout type="note" title="Scope">
  arman-hosseini.ir is a single-author site. The admin service and the Obsidian plugin are part of this project; the public site itself is plain static HTML.
</Callout>

## How does arman-hosseini.ir work?

Astro compiles every route to static HTML at build time. A separate zero-dependency Node service (`admin/`) manages content and builds new releases, and nginx serves the current release through a symlink that is flipped only after a successful build.

The project is organised in four layers:

1. **Presentation** — Astro routes in `src/pages/` render the home, about, projects, journal, tags and contact pages, plus `404`, `sitemap.xml`, `robots.txt`, `llms.txt`, per-language RSS and a web manifest.
2. **Content** — Markdown and MDX under `src/content/{projects,journal}/{en,fa}`, validated by the schema in `src/content.config.ts`.
3. **SEO/AEO** — `src/lib/seo.ts` turns each entry into page metadata, an Open Graph/Twitter card and a JSON-LD `@graph`.
4. **Admin and deploy** — the Node service in `admin/` edits content and builds releases, which `deploy/` serves through nginx.

The publishing path is:

```text
Obsidian ─Vergo MDX Studio─► /api/studio ─► Inbox ─(approve)─► src/content ─► astro build ─► releases/<ts> ─► current (symlink)
Dashboard (/admin) ─► content-meta/overrides.json ─► same build
```

## What can you do with arman-hosseini.ir?

| Capability | What it does | Where it lives |
| --- | --- | --- |
| Bilingual pages | English and Persian, with RTL and hreflang when a pair shares a `translationKey` | `src/content/`, `src/lib/content.ts` |
| SEO/AEO metadata | Title, description, keywords, canonical, Open Graph, Twitter cards and JSON-LD per page | `src/lib/seo.ts` |
| Machine-readable outputs | `sitemap.xml` (hreflang + `lastmod`), `robots.txt`, `llms.txt`, RSS, web manifest | `src/pages/` |
| Built-in MDX components | `Callout`, `Card`, `Tabs`/`Tab`, `YouTube`, `AudioPlayer`, `VideoPlayer` — no import needed | `src/lib/mdx-components.ts` |
| Admin dashboard | Edit SEO, media, translations, draft/disabled status, analytics and rollback | `admin/` |
| Obsidian publishing | Write MDX in Obsidian, compile and send it, then approve it in the dashboard | `../vergo-mdx-studio` |
| Atomic releases | Each build lands in `releases/<timestamp>`; the `current` symlink flips only on success | `admin/lib/build.mjs` |

<Tabs>
  <Tab label="Content authoring" open>

Content is Markdown or MDX with frontmatter validated by `src/content.config.ts`. Files are written by the admin ingest endpoint or by the dashboard; SEO and status overrides live separately in `content-meta/overrides.json` so re-publishing never erases a dashboard edit.

  </Tab>
  <Tab label="Validation">

Every Obsidian submission and dashboard edit is checked against `admin/lib/policy.mjs`: only the built-in components, no imports or `export`, and no server-side APIs (`process`, `require`, `fetch`, …). Fenced code is ignored by the rules.

  </Tab>
  <Tab label="Deploy">

`admin/lib/build.mjs` runs the build into a fresh directory, checks for `index.html`, then moves it to `releases/<timestamp>` and atomically replaces the `current` symlink. A failed build never touches the live site.

  </Tab>

## How do I install and run arman-hosseini.ir?

Requirements: Node.js 20 or newer (from `engines` in `package.json`) and npm. No other runtime is required; the admin service uses only the Node standard library.

```bash
git clone https://github.com/vergoboy/arman-hosseini.git
cd arman-hosseini
npm ci
npm run dev        # local dev server
npm run build      # astro check && astro build → dist/
npm test           # admin API tests (node --test admin/test/*.test.mjs)
```

The validated `package.json` scripts are:

| Script | Command | Purpose |
| --- | --- | --- |
| `npm run dev` | `astro dev` | Local development server |
| `npm run build` | `astro check && astro build` | Type-check and build to `dist/` |
| `npm run preview` | `astro preview` | Preview the built output |
| `npm test` | `node --test admin/test/*.test.mjs` | Admin API tests |
| `npm run admin` | `node admin/server.mjs` | Start the admin service (defaults to `127.0.0.1:4322`) |
| `npm run deploy` | `bash scripts/deploy.sh` | Build and rsync `dist/` to the server as a new release |

## How do I configure arman-hosseini.ir?

The admin service and the build read a small set of environment variables. Names only — never store secrets in the repository.

| Variable | Purpose | Default |
| --- | --- | --- |
| `SITE_DIR` | Root of the site source | the project root |
| `DATA_DIR` | Admin data directory (sessions, builds, inbox) | `./.admin-data` |
| `RELEASES_DIR` | Where built releases are stored | `./releases` |
| `CURRENT_LINK` | Symlink nginx serves | `./current` |
| `ADMIN_HOST` | Admin bind address | `127.0.0.1` |
| `ADMIN_PORT` | Admin port | `4322` |
| `BUILD_CMD` | Command the admin runs to build | `npm run build:site` |
| `KEEP_RELEASES` | How many releases to keep | `5` |
| `SITE_URL` | Canonical site URL | `https://arman-hosseini.ir` |

Deployment settings that are not secrets live in `deploy.config.json` (host, port, user, `remotePath`, `identityFile`, `localDir`, `buildCommand`, `exclude`). Any credential belongs in the git-ignored `.env`; `scripts/deploy.sh` refuses to run if `deploy.config.json` contains a password, passphrase, private key, token or secret field.

## How does arman-hosseini.ir compare with a CMS like WordPress?

Both can publish text in multiple categories. The trade-off is operational weight versus editing convenience.

| Aspect | arman-hosseini.ir | WordPress |
| --- | --- | --- |
| Runtime | Static files served by nginx | PHP + a database |
| Dependencies | Node.js at build time; admin uses no npm packages | Plugins and a database to maintain |
| Editing | Markdown/MDX files, dashboard, or Obsidian | Browser admin UI |
| Performance | Pre-rendered HTML; no per-request rendering | Rendered per request (caching needed) |
| Interactivity | None in content (static site) | Plugins and themes |
| Best for | One author, text-heavy, fast, low-maintenance | Many editors, plugin ecosystem, dynamic features |

A static site is the wrong choice if you need user accounts, comments or content that must change per request without a rebuild. arman-hosseini.ir intentionally has none of those.
